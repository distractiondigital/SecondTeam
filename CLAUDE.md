# Second Team

A local Windows desktop app for film previs. You greybox a set (primitives, posable mannequins, lights), place real cameras, link objects and characters to reference images, then generate AI frames through a managed local ComfyUI backend and assemble a storyboard.

**Full spec: `docs/SPEC.md`. Read it before planning any milestone.**
**Progress tracker: `docs/PROGRESS.md`** (public, milestone level: big features only). Update it at the end of every milestone.
**Working notes: `notes/DEV-NOTES.md`** (git-ignored, private): the detailed decisions log, per-change history and things to know. Log decisions there, not in PROGRESS.

## Stack
Electron + React + TypeScript + Vite · three.js via react-three-fiber + drei · Zustand · ComfyUI (Windows portable) over its HTTP/WebSocket API · electron-builder.

## About the user
- Spencer is a filmmaker/DP and experienced PC builder, but **new to software development**. This is his first app.
- Explain what you're doing in plain language, and briefly define any jargon.
- When a step needs him (installing something, testing, deciding), say exactly what to click or type.
- He tests by using the app, not by reading code. End every milestone with a short **"How to test this"** checklist.

## How we work
1. **One milestone at a time** (see the table in SPEC §6). Don't start the next one until he confirms the current one works.
2. Start each milestone in plan mode: propose the approach, list the files you'll create, and flag any decision he needs to make.
3. **Don't add features that aren't in the spec** without asking. Put ideas in the "Ideas / later" section of PROGRESS.md instead.
4. Commit to Git at the end of each working milestone, with a clear, professional message (what changed for the user; no anecdotes or back-and-forth about Spencer's requests).
5. If something in the spec seems wrong or there's a clearly better approach, say so and explain why before changing course.
6. Keep the app runnable. Never leave it in a broken state at the end of a session.

## Hard rules
- **Local only.** No cloud AI APIs and no telemetry. The only network calls allowed are downloading the backend and models from the pinned manifest.
- **Model licences matter.** He uses outputs for paying clients. Every model in `backend/manifest.json` records its licence. Never add a non-commercial model (e.g. FLUX.2 klein 9B, FLUX.1 dev) without flagging it clearly.
- Don't copy GPL code (e.g. from Krita AI Diffusion) into the project without asking first. Studying it for ideas is fine.
- **Credit everything.** Any new third-party library, model, dataset or asset goes into `src/shared/credits.ts` (the in-app Credits) and `CREDITS.md`, with its licence.
- Commit messages have no `Co-Authored-By` (or other AI attribution) lines.
- Windows paths, and handle spaces in paths.
- Never write outside the project folder, the chosen backend install folder, or the app's folder (`appDataFolder()` in `src/main/settings.ts`: `%LOCALAPPDATA%\SecondTeam` on Windows, `~/Library/Application Support/SecondTeam` on a Mac).

## Commands
- Install dependencies: `npm install` (`start.bat` does this automatically when `package.json` or `package-lock.json` is newer than `node_modules\.install-stamp`)
- Run in dev: `npm run dev`, or double-click `start.bat`
- Tests: `npm test` (Vitest; store/undo, grouping, save round-trip, units)
- Typecheck: `npm run typecheck`
- Build: `npm run build` (typecheck + electron-vite build into `out/`)
- AI backend (dev): `node scripts/fetch-backend.mjs` downloads ComfyUI portable + the models from `backend/manifest.json` into `ComfyUI\` (git-ignored), resuming and SHA256-checking. Add a model = add a manifest entry with its licence (`commercial: true` is enforced by a test).
- Installer: `npm run dist` (electron-builder NSIS into `release/`, per-machine into Program Files (admin prompt), unsigned; the app folder is read-only at runtime, so never write next to the exe; `build/icon.png` from `build/make-icon.ps1`). The renderer's libraries are devDependencies (bundled by electron-vite); the packaged app needs no node_modules. `backend/` (manifest + workflows) is packaged and read from `app.getAppPath()`.
- Layout: `src/main` (Electron main; `projectFiles.ts` = save/open IPC), `src/preload` (IPC bridge, typed in `src/preload/api.d.ts`), `src/shared` (project.json schema, primitives), `src/renderer/src` (`state/` Zustand stores + actions, `viewport/`, `panels/`). Scene units: 1 unit = 1 metre, rotations stored in degrees, Y up.
- Document store (`state/documentStore.ts`) is the only place that changes the project; every change is an undo step (gizmo drags batched with `beginGesture`/`endGesture`). UI-only state lives in `state/uiStore.ts`.
- Placement maths (local/world matrices, re-parenting, moving several things) is in `src/shared/transforms.ts` (pure, tested); takes a nodes record, so it works on a shot's view (`editedNodes`) too. Structural changes that re-parent (`groupNodes`, `ungroup`, `moveNodes` = Outliner drag & drop) go through `reparentInPlace` in the store, which keeps world placement in Master and in every shot's overrides.
- Selection & navigation (M11 A): `viewport/BoxSelect.tsx` (left-drag rectangle; `viewportBridge.boxSelecting` stops the release counting as a click), `SelectionGizmo.tsx` (`SingleGizmo` / `MultiGizmo` on a helper pivot), `FreeFly.tsx` (right-mouse fly in the free view; shared keys in `flyInput.ts` with `LookThrough.tsx`), `LightAim.tsx` (selected sun/spot aim line + spot footprint, raycasts the live set; figures via their posing skeleton). Recent projects: `src/main/recentProjects.ts` (`recent.json`; IPC `project:recent|openRecent|forgetRecent`, main only opens listed folders), UI `panels/RecentProjects.tsx` (`StartScreen` over the viewport, `RecentMenu` in the toolbar).
- `electron-vite dev` hot-reloads the UI but not `src/main` or `src/preload`: restart the app after changing those. Its file watcher sometimes misses rapid edits (you get a stale module, e.g. "X is not defined" although typecheck passes); restart the dev server when that happens.
- Figures: skeleton, proportions, limits and presets live in `src/shared/mannequin.ts` (pure, tested). `viewport/MannequinView.tsx` renders them; joint groups are named `<id>:<joint>`; `viewport/JointGizmo.tsx` poses them.
- Human figures (M10): `MannequinNode.style` 'human'|'mannequin', `body` (gender/age/muscle/weight 0-1), `appearance` (hair, eyebrows, garments per slot, colours), `expression`, `hands`; all per-shot overridable; `CastMember.look` shared by linked figures (synced in `updateNodes`). Pure maths in `src/shared/humanBody.ts` (target blending with MakeHuman macro weights, `fitHuman` = body + our skeleton's joint positions, breast sliders = MakeHuman's breast targets in `targetWeights`, proxies `fitProxy`/`proxySkin`/`visibleBody`, expressions, hand curls; tested). Data in `figures/` (from `scripts/figures/build-figure-data.mjs` + `build-proxies.mjs`; sources in git-ignored `tools/makehuman/`), served by IPC `figures:read` (`src/main/figureFiles.ts`). `viewport/HumanFigure.tsx` = invisible fitted mannequin (clicking, gizmo, pose pass) + `HumanView.tsx` (skinned body retargeted from our 17 joints, finger curls, proxies). Pass shaders include three's skinning chunks and cut out masked cards (`renderPasses.ts`). Dev test hook: `SECONDTEAM_OPEN=<folder>` opens a project without the dialog (not in packaged builds).
- Posing 2 (M11 B): `src/shared/posing.ts` (pure, tested): `jointOffsets` (MannequinView places joints with it), `forwardKinematics`, `solveReach` (two-bone IK, pole continuity, swivel search under limits), `solveLookAt`, `effectivePose` = stored pose + `MannequinNode.plants` + `lookAt` (applied when drawing, never stored). Renderer: `viewport/figurePose.ts` (`useEffectivePose`, `figureProportions` = a human's fitted proportions, cached `fitFor`, look targets per shot via `SceneNodesContext` in `viewport/sceneContext.ts`), `GrabHandle.tsx` (hold-and-drag ball, W/S depth, Space snap, `viewportBridge.grabbing` silences shortcuts), `ReachHandles.tsx` (hands/feet/hips/look point; snapping via `viewport/surfaces.ts`). Store: `updatePose(id, { joints, pelvisOffset, plants })`. Dev-only test hook: `window.__viewport` = { camera, scene, gl, controls } (`RendererHandle.tsx`).
- Shots & AI (M11 C): `descriptionFor(entity, scene, shot)` in `shared/project.ts` resolves a cast member's/prop's text (shot `CameraNode.descriptions` → `Scene.descriptions` → usual), store `setDescriptionTweak`; UI in `panels/CastProps.tsx` `DescriptionSection`. Materials: `PrimitiveNode.material` (`MATERIALS`), looks in `viewport/materials.ts` (`studioReflections` = RoomEnvironment PMREM for shiny ones), prompt words `materialWords` in `shared/prompt.ts`. Compare: `viewer.compare` + `compareMode` in `state/generation.ts` (`openCompare`, `stepTake(dir, side)`), `panels/TakeViewer.tsx`. ComfyUI runs with `--preview-method taesd` (decoders ship in the portable's `models\vae_approx`).
- Cameras: maths in `src/shared/camera.ts` (pure, tested); `viewport/CameraView.tsx` (body/frustum), `viewport/LookThrough.tsx` (camera view + fly controls), `panels/FrameOverlay.tsx` (frame/HUD), `viewport/ShotTracker.tsx` (readouts + thumbnails via `viewport/renderShot.ts`). Mark any viewport-only object with `userData.helper = true` so it stays out of renders.
- Depth of field (M13): maths in `src/shared/depthOfField.ts` (thin lens: `blurCircle`, `focusRange`, `shotFocus`, `focusWords`; pure, tested); `CameraNode.aperture` (stop, schema v15). Renderer `viewport/depthOfField.ts` (`DepthOfField`: half-res golden-spiral gather + depth-aware blend, writes depth) used by `renderShot(…, focus)` (thumbnails, board, Clay exports; `focusOf` in `boardClay.ts`) and `viewport/LiveDepthOfField.tsx` (camera view, `useFrame` priority 1, helpers drawn after; `uiStore.dofPreview`). Auto focus on a human uses the real corneas (`corneaPoints` in `shared/humanBody.ts`; `HumanView` hangs `userData.focusEye` markers on the head bone), a mannequin its skeleton's `kp:eye` points. Click to focus: `viewport/FocusPick.tsx` (`uiStore.focusPicking`). UI: `panels/FocusControls.tsx`. Render passes stay sharp.
- Clay lighting (M14): `LightNode.size` (metres for point/spot, degrees for the sun; schema v16 migrates softness; `SIZE_PRESETS`, `apparentSize` in `shared/lighting.ts`). Shadows: `shadows="basic"` + `viewport/softShadows.ts` patches three's BASIC `getShadow`/`getPointShadow` into PCSS (light size via `shadow.radius`: sun = depth range × tan(angle) / frustum width, spot = −size / (2 tan half-cone), point = size), shadows cast by front faces (`castFromFrontFaces` before each clay render) with a small normal offset (no slope/receiver-plane bias: it facets curved faces); a penumbra wider than the cap fades the shadow out. `viewport/clayPost.ts` (`ClayPost`: AO at half res + depth-aware blur, then DoF (full-res gather) or plain output) replaced `depthOfField.ts`. AO is never multiplied over the picture: `prepareOcclusion(scene)` gives standard materials a `ST_AO` define + shared uniforms (patched `aomap_fragment`, edge-aware upsample, multi-bounce) so it scales only indirect light; `post.withOcclusion(draw)` draws the set with the last AO (live = previous frame; `renderShot` draws twice, first with output 'none'); `LiveClayPost.tsx` runs in all Clay views. Soft light: the same patch makes each light a sphere/disc of its size in `RE_Direct_Physical` (`stSourceNL` = Frostbite sphere-light illuminance, roughness widened by half the angular size, highlights keep the plain cosine, shadow map eased off on the horizon band via `stShadowBlend`); sizes reach the shader through shared Float32Array uniforms on `ShaderLib.standard/physical`, filled in three's light order by `updateLightSizes(scene)` before each clay render (lights carry `userData.sourceSize`). Bounce: `bounceScale` (`shared/environment.ts`) brightens the hemisphere fill's ground colour by the sun on the ground (`sunOnGround` in `EnvironmentView.tsx`). When testing over CDP, import app modules by the URL in `performance.getEntriesByType('resource')` (Vite adds `?t=`), and `/@fs/C:/…` for `src/shared`.
- Shot window (picture-in-picture): `panels/ShotPip.tsx` (layout, shows while a shot is active, not looked through, on the Set; `uiStore.pipOpen` remembered, `pipElement` = the picture area) + `viewport/PipRender.tsx` (mounted only while `pipElement` is set: its `useFrame` priority 10 draws the shot's hidden lit copy (`shotScenes`, always Clay, its own shadow maps) into that rectangle with viewport + scissor and its own `ClayPost`, then restores the live set's light sizes). Camera steering is shared with camera view in `viewport/useShotFly.ts` (`useShotFly({ element, shotId, rollAnytime })` returns the working pose). The axis gizmo runs at render priority 2 in Clay so drei's Hud doesn't redraw the set over the Clay post.
- Scenes & shots: a project has numbered scenes (`Scene.number`, optional title); shots are camera nodes named 1A, 1B… (`nextShotName` in `src/shared/camera.ts`); the camera body/format is project-wide (`project.camera`, read with `opticsFor(kit, focalLength)`); only lens/focus/placement are per shot. Cameras are hidden from the Outliner and never grouped.
- Master scene + per-shot overrides: `src/shared/overrides.ts` (merge rules). In the store, every edit goes through `edit()` → `write()`, which turns per-shot fields into the active shot's overrides. UI code must read nodes via `editedNodes(s)` (the shot being edited) or `sceneForShot(s, id)`, never raw `activeScene(s).nodes`, unless it deliberately wants Master. `viewport/ShotScenes.tsx` keeps a hidden per-shot copy of the set for thumbnails/renders.
- Lights: maths and the lighting phrase in `src/shared/lighting.ts` (pure, tested); `viewport/LightView.tsx` draws the three.js light (only in Clay shading) and its helper icon. Clay uses each object's own colour ("Material" in the UI, `color` in the file).
- Environment: `src/shared/environment.ts` (time of day 0-24 h → sky/fill colours, labels, prompt phrase; pure, tested). `Scene.environment`, per-shot `CameraNode.environment` (null = the scene's); read with `environmentFor(state, shotId)`, change with `setEnvironment` / `setShotOwnEnvironment`. `viewport/EnvironmentView.tsx` sets the sky as `scene.background` (so passes' `onBlack` clears it) plus a hemisphere fill and `FogExp2` (`fogDensity`; `onBlack` in renderPasses removes fog from depth/normals/ID); `RenderFloor` takes the ground colour. Clay viewport with lights shows the floor instead of the grid. The time phrase starts `ShotInfo.lighting` (`viewport/shotInfo.ts`).
- Render passes: pure maths in `src/shared/passes.ts` (SDXL size, COCO-18 keypoints, depth curve, ID legend; tested); `viewport/renderPasses.ts` renders them from the hidden per-shot scenes by swapping mesh materials (skips helpers and `userData.grid`; `userData.floor` is the automatic floor, `userData.workLight` the Work lights); `state/passes.ts` renders + saves (IPC `passes:write` in `src/main/passFiles.ts`) and drives `panels/PassViewer.tsx`. `viewport/RendererHandle.tsx` exposes the WebGL renderer outside the canvas. Colours for raw passes: don't go through `three.Color` (it converts to linear); write bytes directly.
- Testing over CDP: `import('/src/...')` from the page can return a *different* module instance than the app's after HMR updates (Vite adds `?t=` to changed modules). Drive UI state through the DOM (click the real buttons) or reload the page first.
- Generation (M6): main process only (`src/main/backend/`): `comfyProcess.ts` spawns the portable ComfyUI hidden on a free port (log in `%LOCALAPPDATA%\SecondTeam\logs\comfyui.log`, pid file to kill leftovers after a dev reload), `comfyClient.ts` (HTTP + WebSocket), `workflow.ts` fills `backend/workflows/*.json` `{{placeholders}}`, `generation.ts` (`GenerationBackend` + ComfyBackend), `takeFiles.ts` (takes on disk, never in project.json). Renderer: `state/generation.ts`, `panels/TakeStrip.tsx`, `TakeViewer.tsx`, `GenerateSection.tsx`, `BackendStatus.tsx`. Types shared in `src/shared/takes.ts`; prompt + settings maths in `src/shared/prompt.ts`.
- Continuity (M7): `project.cast` / `project.props` (`CastMember`, `Prop` in `shared/project.ts`), linked by `MannequinNode.castId` and `PrimitiveNode`/`GroupNode.propId`, or an object's own `description`. `shared/passes.ts` `entityKey` / `idLegend` decide each mesh's region (nearest linked or described node upward). Generation composes `backend/workflows/sdxl-continuity.json` with the per-entity fragments in `backend/workflows/fragments/` (`composeWorkflow` in `src/main/backend/workflow.ts`; fragment node ids are `<prefix>.<id>`, `{{in:x}}` placeholders are links). Reference images live in the project (`assets\cast|props\<id>\`, `assets\style\`), copied in by `src/main/assetFiles.ts`. UI: `panels/CastProps.tsx` (tabs, lists, EntityProperties, LinkSection), `panels/ReferenceImages.tsx`. Circle take = `CameraNode.circleTake`.
- Storyboard (M8): `project.board.order` (own order across scenes; `boardShots` in `src/shared/board.ts` merges it with the live shots), `CameraNode.boardText` (null = use `description`) and `dialogue`; store actions `setBoardOrder`, `updatePanel`. UI: `uiStore.view` ('set' | 'board'), `panels/BoardView.tsx`, `panels/BoardExport.tsx`; the Set workspace stays mounted (hidden) while the board shows. Board AI | Clay (`uiStore.boardImage`): while the board shows, `ShotScenes` builds hidden copies for every scene's shots (`sceneOfShot` finds a shot's own scene; `sceneForShot` uses it) and `ShotTracker` renders them into `uiStore.boardClay` (`viewport/boardClay.ts`; Clay exports render at 1920 px and send PNG data URLs in `BoardExportSpec.clayImages`). PDF = `src/shared/boardHtml.ts` (pure, tested) printed by a hidden window in `src/main/boardExport.ts` (`printToPDF`); exports go to `<project>\exports\`.
